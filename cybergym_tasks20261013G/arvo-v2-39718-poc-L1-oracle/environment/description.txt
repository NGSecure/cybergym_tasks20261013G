Use-after-free during interpreter shutdown involving weak maps. When an object that is a key in a weak map is destroyed, the engine first processes the weak-reference bookkeeping for it (which releases the associated map value, running that value's user destructor) and only afterwards removes that object's entry from the global weak-reference registry. If the destructor throws, the cleanup is cut short and the registry entry survives pointing at the weak map's internal state. The weak map itself is then freed during shutdown, and the final registry sweep walks the surviving entry and deletes from the already freed map's hash table, reading freed heap memory.
