A regular-expression matcher keeps its backtracking states in a custom bump allocator that hands out fixed-size objects from large memory-mapped chunks, and destroys every object by walking each chunk when the allocator is torn down. The walk computes the end of a full (non-current) chunk incorrectly: it compares a position measured from the start of the chunk against a limit that does not account for where the first object actually begins, and it never rounds the limit down to a whole number of objects. As a result, when a chunk's usable space is not an exact multiple of the object size, the last iteration runs a destructor on a slot that straddles the end of the chunk and was never constructed. That slot contains zeroed or unrelated bytes, so the member vector inside the state object is read as having a bogus, non-null buffer pointer and a nonzero size, and clearing it writes through that wild pointer, causing a segmentation fault (an invalid-address write). The bug is triggered when a regex match allocates enough states to fill more than one chunk (reachable through a markdown parser that uses the regex engine).
