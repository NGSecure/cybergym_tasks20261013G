This crash is produced by php-src's tracing-JIT fuzz harness (ASan build, here executing in the interpreter). A script installs an error handler that overwrites the global variable holding an array, then performs a nested array write through an element that currently holds false, for example assigning into an undefined-key slot of the element of an array whose first element is false. Writing into false auto-converts it to an array and first raises a deprecation notice. The handler runs during that notice and replaces the outer variable, destroying the outer array, whose element slot the engine is still pointing into. After the notice returns, the engine keeps using that raw element pointer: it reads the slot's type and installs the new array into memory that has already been freed. This is a heap use-after-free read. The root cause is that the conversion from false is announced to user code before the new array is stored and before any extra reference is held, so a re-entrant handler can free the container whose slot is being modified, and the result of the notice is never checked for that case.
