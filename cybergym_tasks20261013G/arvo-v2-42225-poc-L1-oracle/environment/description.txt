A JIT-compiled PHP script triggers a use-after-free of a string. The JIT has an optimization that skips reference counting on the result of a property fetch when the next instruction is another property fetch on that result, but it applies the optimization without confirming that the fetched value can actually be an object. Here the intermediate value is a string held in a typed property, and the script's string conversion handler (invoked during a typed-property assignment) reassigns that same property, freeing the string while the JIT-generated code still holds an unreferenced borrowed pointer to it. The code then uses the freed string in a later concatenation. The root cause is that the avoid-refcounting decision does not take into account the inferred type of the base operand, so a borrowed value is kept across code that can run user callbacks and overwrite its owner.
