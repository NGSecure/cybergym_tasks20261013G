A heap-buffer-overflow READ occurs in the HTTP header-attribute parser used by the multipart form-data parser (ASan build), triggered by a malformed Content-Type value. The parser scans a semicolon/comma-separated list of name[=value] items held in a small, exactly sized heap copy of the header text. For each item it records the position just past the terminating delimiter, and after an item that has no value it resumes the next iteration one byte beyond that recorded position, assuming the delimiter was a real separator that is followed by more text. When the item is an attribute with no value (no equals sign) that is the last thing before the string's terminating NUL, the recorded position already points at the NUL, so the resume step skips over the terminator and the scan keeps reading past the end of the allocation looking for a delimiter. The value-detection logic also inspects the byte before the recorded position instead of the delimiter itself, which makes this off-by-one worse. In the same path, a boundary parameter that is present but empty is accepted and the caller then dereferences and indexes into its zero-length value.
