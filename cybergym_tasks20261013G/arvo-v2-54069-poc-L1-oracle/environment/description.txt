Summary: A heap-use-after-free read in the CUPS PostScript raster interpreter, triggered when interpreting a crafted PPD/PostScript command stream that causes an operand stack to be duplicated.

Root cause: When the interpreter duplicates an operand stack, the copy routine walks the source stack's object array and, for each element, passes a pointer to that element (an address inside the source buffer, st->objs + n) straight into push_stack. push_stack checks whether the destination stack is full and, if so, grows its backing object array with realloc; that realloc frees the old buffer. Because the source and destination share the same growing array during this copy, the just-freed old buffer is exactly where the caller's element pointer points. push_stack then performs a block copy of the 72-byte object from that dangling pointer into the freshly reallocated array, reading from freed heap memory (a use-after-free READ of 72 bytes, the size of one stack object). The value that grows is the stack's capacity (driving the realloc); the bad operation is a READ through a stale pointer into the freed pre-realloc buffer.

Fix: The copy loop is changed to first copy the source object into a local temporary on the stack, then pass the address of that temporary to push_stack. This breaks the aliasing between the element pointer and the array being reallocated, so even if push_stack reallocates and frees the old buffer, the source data it copies from is the local temporary and no longer lives in freed memory.

fix_commit judgment: matches. The commit edits exactly the stack-duplication loop, inserting a local temporary object copy before the push_stack call so the pointer handed to push_stack no longer references the array that push_stack may realloc/free. That is precisely the aliasing condition responsible for the use-after-free read observed in the crash, so the fix_commit is correct for this crash.
