A DNS packet decoder computes the length of a variable-length domain-name field using the wrong bound. When decoding a name that sits partway into the packet, it passes the distance from the start of the whole packet to the end of the data, instead of the number of bytes remaining from the name's own starting position. The length routine treats that value as the size of the buffer beginning at the name, so its notion of the buffer end overshoots the real end of the input by the name's offset within the packet. A truncated name whose labels run to the end of the input is therefore walked past the allocation, causing a one-byte heap out-of-bounds read.
