A SQL parser harness crashes when two constant expressions in a GROUP BY list are compared for equality. The comparison casts a string constant to an integer, and the string-to-number parser accepts an optional exponent marker. After consuming the marker character the parser advances its position without re-checking that any input remains, so when the string ends right after the marker it goes on to read the byte beyond the end of the string buffer (a one-byte stack over-read). The exponent branch needs a bounds check after the marker is consumed.
