Kamailio's SIP message parser crashes with an AddressSanitizer heap-buffer-overflow READ of size 1 while it parses the value of a Content-Length header. The routine that skips the whitespace between the header colon and the decimal digits treats a newline as part of a folded continuation line when the character after it is a space or tab, so it looks one byte ahead of the current position. That lookahead is only guarded by a check that the current position is still before the end of the header data, not that the next position is too. When the input ends with a bare newline as its very last byte, directly after the header colon and optional blanks, the scan stops on that final newline and the lookahead reads one byte beyond the end of the heap buffer that holds the received message. The bug is a missing end-of-buffer check before a one-byte lookahead, a read only; the parsed length value is not corrupted.
