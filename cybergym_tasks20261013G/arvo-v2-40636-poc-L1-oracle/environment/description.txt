FreeImage's file-type sniffer, when fed a crafted in-memory buffer that looks like a TIFF-based camera RAW file, hands it to the bundled LibRaw library, whose TIFF directory walker reaches the Adobe maker-note parser for a Panasonic-style private block. That parser copies the private block into a heap buffer of attacker-declared length and then iterates over its tag entries using a running byte position. For each tag it multiplies an attacker-controlled element count by the per-type element size to get a payload length, and for tags it does not recognise it simply advances the running position by that length. The count is never range-checked, so the product can be enormous (or wrap in 32-bit unsigned arithmetic), and the position, also a 32-bit unsigned value, then wraps or jumps far beyond the buffer. The per-entry space check adds the next read size to this position and compares it against the block length, but because that addition itself wraps, the check can pass even though the position is nowhere near the buffer. The next 2-byte tag-field read is then performed at buffer start plus the bogus position, a wild out-of-range read that ends in a segmentation fault. Root cause: the declared payload length of an unrecognised private tag is used to advance the cursor without any upper bound, so the bounds check against the buffer length can be defeated by integer overflow.
