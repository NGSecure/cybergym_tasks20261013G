While reading an image's embedded EXIF metadata, the library's EXIF block parser locates the EXIF application segment inside a larger buffer and takes a 16-bit segment length straight from the untrusted bytes. It then derives the number of usable bytes by subtracting the 2-byte length field from that declared length, using unsigned arithmetic, and never checks that the declared length is at least 2 or that it fits within the bytes actually remaining in the buffer. A declared length that is too small makes the subtraction wrap around to a huge value, and an overlong one claims more data than exists, so the later bounds checks on the directory offset and entry table are made against a size that is far larger than the real heap allocation. The directory walker then trusts that inflated size and reads 16-bit fields of directory entries beyond the end of the small heap buffer holding the metadata, a one-byte heap out-of-bounds read. The defect is an unvalidated segment length that corrupts the available-size bookkeeping, and the overflow is a read of the input metadata buffer, not a write.
