This crash is produced by php-src's tracing-JIT fuzz harness (ASan build), which records hot execution paths of a PHP script and compiles them to native code. The script runs a loop in which an integer variable is added to itself, then rebound by reference to another (undefined) variable, and added to itself again. The trace's type analysis sees the variable as an integer coming from a loop-carried merge point and decides that the type guard on its incoming value is redundant because it was "already checked" as integer by an earlier guard. That reasoning ignores that the variable's slot may by then hold a reference wrapper (the reference binding happens inside the loop body), so the guard that should have caught the type change is omitted. The compiled code therefore passes the slot to the generic addition helper as if it held a plain value, but the slot actually holds a pointer to a reference object; the helper reads the operand's type through a wild address, giving a wild-address read (SEGV). The root cause is that the "guard already checked" shortcut for integer-typed loop merge variables does not exclude variables that may be references.
