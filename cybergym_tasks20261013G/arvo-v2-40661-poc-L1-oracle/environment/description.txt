dav1d, VideoLAN's AV1 video decoder, built with AddressSanitizer, crashes with a heap-buffer-overflow WRITE on a worker thread while running the constrained directional enhancement post-filter on a crafted multi-frame bitstream. The decoder keeps a persistent per-frame-context line buffer in which the filter saves two rows of unfiltered pixels per superblock row, for the luma and both chroma planes. At the start of each frame this buffer is reallocated and its per-plane base pointers are recomputed only when the product of the plane stride and the number of superblock rows differs from the value remembered from the previous frame (or when the resize-copy requirement changes); the superblock-row count itself is never compared. If a later frame has a different frame height, and hence a different number of superblock rows, but a stride that makes the product come out the same, the old allocation and the old stride-dependent layout are kept. The filter then indexes the buffer by superblock row using the new frame's stride and row count, so the two-row save lands at an offset that does not fit the stale layout, and the copy of one stride-sized row runs past the end of the heap chunk. The fix makes the allocation also depend on the superblock-row count remembered from the last time it was sized.
