mruby's bytecode compiler has a peephole optimizer that, when emitting a register move right after an "add/subtract small immediate" instruction, can rewind the output position past the preceding move and fold a preceding integer-constant load plus the arithmetic into a single constant load. The folding checks that the arithmetic instruction itself is not a jump target, but it does not check that the earlier instruction it rewinds into (the constant load) is not the most recently recorded jump-target label. When it is, the compiler discards and rewrites code that a pending jump was already bound to, so the recorded jump destination no longer matches the instruction layout and the final instruction sequence ends up shorter than a label or branch offset assumes. The bytecode is then run by the VM, whose fetch of the next opcode reads one byte beyond the end of the small heap-allocated instruction buffer, a heap-buffer-overflow read of a single byte. The condition is closed by skipping the constant-folding rewrite whenever the instruction it would rewind into sits at the last label position.
