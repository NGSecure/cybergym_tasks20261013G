A Parquet column using the delta-encoded byte-array scheme (each value stored as a prefix length plus a suffix, where the prefix is meant to be copied from the previous decoded value) is decoded without validating the stored prefix lengths. The decoder sums the prefix and suffix lengths into a 64-bit size without any overflow check, sizes a scratch buffer from that sum, and then copies "prefix length" bytes from the previously reconstructed value into the output. The prefix lengths come straight from the file and may be negative or larger than the previous value actually is; the only guard is a debug-only assertion that is compiled out in release builds. A crafted file therefore makes the copy length far exceed the previous value, so the source range (the previous value's storage) and the destination range (the freshly resized scratch buffer) end up overlapping, which AddressSanitizer reports as a memcpy parameter overlap while reading a Parquet file through the Arrow reader. The fix rejects negative lengths, checks the length sums for overflow, and throws if a prefix length exceeds the previous value's length.
