mruby's native-to-Ruby method call helper (used when C code calls back into a Ruby method, such as during constant lookup) writes the receiver, arguments and block into the VM value stack at an offset equal to the current frame's register count. Before doing so it grows the stack only by the argument count plus a small constant, forgetting to add that frame offset. When the current frame already sits close to the end of the stack allocation, the growth request is considered satisfied even though the slots actually written lie beyond the allocated array, so storing the receiver/arguments overflows the heap-allocated stack by one value. The condition is closed by sizing the stack growth as the frame offset plus the argument count plus the constant.
