The Sleuth Kit's NTFS module, while opening a crafted image and processing a file's attribute list, walks a compressed non-resident data attribute decompression unit by unit and, once a unit has been decompressed, zeroes the part of the output buffer that lies beyond the attribute's initialized size. It computes the number of initialized bytes remaining as the initialized size minus the current file offset in signed 64-bit arithmetic, but never checks that the offset has not already passed the initialized size (which a corrupted attribute with a small initialized size makes possible). The remaining count then goes negative, and it is used both as an index into the decompression buffer and to derive the length of the zero-fill, so the buffer is cleared starting at a wild address before its start with an enormous, negative-looking length. This surfaces under ASan as a negative-size-param error in the memset call.
