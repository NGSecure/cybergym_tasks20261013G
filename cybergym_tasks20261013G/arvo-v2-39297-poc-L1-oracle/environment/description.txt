This crash is produced by php-src's function-JIT fuzz harness (ASan build). The script binds a reference to a typed object property (nullable type) and then performs an assignment whose result is used (for example, passed to a function) with a value that is incompatible with the property type, so the engine throws a type error. The bug is in the native code generator for assignment through a typed reference: the generated fast path calls a runtime helper that performs the checked assignment, but the helper's return value (the assigned value) is discarded and the JIT never copies it into the instruction's result slot. When the result is consumed, the slot holds stale or uninitialized data left over from earlier execution, and the compiled code later treats it as a live reference-counted value, adjusting the reference count of memory that has already been released (the exception message string freed during request shutdown). The outcome is a heap use-after-free read when the leftover value is destroyed during engine shutdown. It only occurs for code compiled to native code; the interpreter writes the result correctly.
