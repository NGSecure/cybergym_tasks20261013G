The PHP engine's bytecode optimizer reads past the end of a heap-allocated opcode array while simplifying jumps. When an unconditional jump targets a three-way conditional jump instruction (one that carries two destination addresses), the optimizer overwrites the jump with a verbatim copy of that target instruction. On builds where jump destinations are stored as relative offsets from the instruction itself rather than as absolute pointers, the copied instruction keeps offsets that were computed relative to its original position, so after being moved they point somewhere else entirely. The later jump-threading logic follows these stale destinations, which land beyond the end of the opcode buffer, and dereferences the instruction found there, causing an out-of-bounds heap read. The root cause is that the copied instruction's jump destinations are not recomputed for its new location; the fix re-encodes both destination fields relative to the new position after the copy.
