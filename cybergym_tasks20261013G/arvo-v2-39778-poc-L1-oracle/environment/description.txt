This is a heap use-after-free read in the PHP engine, triggered while running registered shutdown callbacks. A class constructor registers a shutdown callback that names one of its own methods as a plain "Class::method" string. While the constructor runs, the callable check resolves that string against the currently executing object and records that object as the call target inside the callback entry that is kept for later. The registry only takes a reference on the callback name, not on the recorded target object. The script creates the object as a discarded temporary, so as soon as the statement ends its last reference is dropped and the object is freed, while the stored entry still points at it. At request shutdown the callback is invoked from the saved entry; the argument-type check on the internal call re-validates the callable string, starts from the stale object pointer, and reads the class field of the freed object to test class relationships, which is a read of freed heap memory. The root cause is that the callback registry keeps a borrowed, non-refcounted object pointer in its cached call information, so the object can be destroyed before the callback fires. The fix makes the registry hold a reference to the cached target object and release it when the entry is destroyed.
