This crash comes from php-src's tracing-JIT fuzz harness (ASan build, 32-bit). A script loops while building nested arrays: it reads an element of an inner array (an array that is itself fetched as a temporary value), passes it to a function call, and stores the call result into another nested element. Once the loop is compiled into a native trace, a type guard on the element read fails (the key is missing) and the generated code escapes back to the interpreter, which re-executes the array-read instruction. The native code had already dropped the reference it held on that temporary array operand, but the escape path does not give the reference back, so the interpreter releases the same temporary a second time. The reference count therefore ends up lower than the number of real owners and the array is freed while still reachable. The next array-assignment instruction then reads the refcount of the freed array, a heap use-after-free read. It only happens for code that has been JIT-compiled and then deoptimized through this exit path.
