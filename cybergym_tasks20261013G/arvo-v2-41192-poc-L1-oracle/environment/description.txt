This crash is produced by php-src's tracing-JIT fuzz harness (ASan build). A hot loop in a PHP function is compiled to native code; it uses a bit shift with a negative shift count (or a modulo by zero) whose operands are intermediate temporaries, after earlier statements in the loop built nested arrays and string values. The native code generator keeps such temporaries in CPU registers and does not write them back to their frame slots on that path. When the shift or modulo fails, the shared error stub throws the arithmetic error and then releases the instruction's temporary operands by reading them out of their frame slots. Because the register-held values were never stored there, the slots still contain stale values left by earlier instructions, whose referents were already released, so the stub drops a reference on dead data. The slots are also not cleared, so the exception unwinding that follows releases the same stale values again. The outcome is a heap use-after-free read (a reference count decremented on freed memory) while an array holding a freed string is destroyed during exception handling. It only occurs for JIT-compiled code; the interpreter always keeps operands in their slots.
