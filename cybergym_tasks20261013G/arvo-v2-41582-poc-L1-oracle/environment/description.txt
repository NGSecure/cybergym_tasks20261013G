A model importer for a legacy 3D-modeller file format (ASan build) reads a fixed-offset version tag from the file header and, when the tag is not one of the recognized versions, emits a warning log message that includes the tag text. The tag is taken as a pointer into the in-memory file buffer and passed to the log formatter as a plain C string, i.e. a read that continues until a NUL byte is found. Nothing guarantees a terminator: the version bytes sit near the end of the input buffer, and a short file whose remaining bytes contain no NUL makes the string length scan run past the end of the heap allocation that holds the whole file. Root cause: an unterminated, non-length-bounded slice of the raw input is treated as a NUL-terminated string when building the log message, so the formatter's strlen reads out of bounds.
