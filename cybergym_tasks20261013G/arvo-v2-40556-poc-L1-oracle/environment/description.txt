This crash comes from php-src's tracing-JIT fuzz harness (ASan build). A script uses an undefined variable as the key of an array write (for example nested assignments such as $a[$undefined] = ...) while a user error handler is installed whose only action is to clear the variable that holds the array being modified. The JIT runtime helper that fetches the element for writing emits the "undefined variable" warning, the handler drops the last reference to the array, and the helper correctly notices the array was destroyed and returns failure, but no exception is pending. In that case the helper returns without initializing the instruction's result slot, which still holds a stale value left by an earlier instruction (an object that was freed together with the array). Only the exception-pending case cleared the slot. At request shutdown the leftover stale slot is destroyed like a live refcounted value, so its reference count is decremented on freed memory, a heap use-after-free read. The interpreter path does not have the problem; it only occurs in JIT-compiled code.
