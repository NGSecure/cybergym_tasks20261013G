The PHP engine's bytecode optimizer reads one byte before the start of a heap-allocated opcode array while rebuilding variable live ranges after optimization. For a null-coalescing assignment on an array element whose key and default are compile-time constants, the optimizer can fold away one branch of the coalesce. The live-range builder still assumes the temporary's consumer is the instruction that releases it on the non-null path, and walks backwards over preceding release instructions to find the start of that block. When the surviving consumer is not such a release instruction, the backward walk steps past the first opcode and inspects memory just before the array. The root cause is a missing check that the consumer really is the expected release instruction; the fix emits an ordinary live range in that case instead of the special two-range handling.
