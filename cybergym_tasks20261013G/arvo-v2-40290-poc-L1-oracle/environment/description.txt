matio's MAT v7.3 reader passes the file to a bundled HDF5 library, which decodes each dataset's storage-layout message while loading the dataset. For chunked storage the message records a dimensionality count that includes one extra trailing dimension for the element size, and the library derives the dataset's real rank as that count minus one. The decoder only rejects a count of zero or one that is too large, so a crafted file can declare a chunked layout with a count of exactly one, giving a rank of zero. Later, when a read builds the per-chunk file selections for a whole-extent selection, the code assumes at least one dimension exists and starts its chunk-advance logic by taking the index of the last dimension as rank minus one, which becomes minus one for a zero-rank layout. It then uses that negative value to index fixed-size per-dimension coordinate arrays, reading and writing one element before the start of the array. The missing piece is validation, when the layout message is parsed, that a chunked layout has at least two stored dimensions.
