matio's MAT v7.3 reader passes the file to its bundled HDF5 library, which iterates the root group and opens each dataset by loading its object header and decoding the datatype message stored in it. A header chunk's raw bytes live in a heap buffer sized exactly from the chunk length recorded in the header, and the datatype decoder is handed a pointer into that buffer but consumes fields at hard-coded offsets without ever being told, or checking, how many bytes the message actually has. It reads a fixed 8-byte prefix (class/version/flags plus the element size) and then, depending on the class, a class-specific property block. For the "time" class this block is a 16-bit precision value, read unconditionally. If a crafted or truncated file declares a datatype message whose recorded size is shorter than the data the decoder expects, so that the message ends right at the end of the chunk buffer, the property read runs past the end of the allocation, a small heap out-of-bounds read. The defect is that the decoder lacks an end-of-message bound on its reads, so any class's fixed-width fields can overrun a short message.
