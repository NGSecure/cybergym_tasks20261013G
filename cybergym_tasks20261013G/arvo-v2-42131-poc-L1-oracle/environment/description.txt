c-blosc2's chunk-decompression path can dispatch a block to a user-registered N-dimensional codec (the 4x4-cell variant of the "ndlz" family). That codec begins by reading a two-dimension block shape directly from the first bytes of the compressed block, and immediately zero-fills a region of width times height bytes at the start of the destination buffer, before any decoding. The two dimensions are attacker-controlled 32-bit values, and the codec never compares their product against the size of the destination buffer the caller actually provided (which is only the block's nominal uncompressed size, allocated by the decompression context). A crafted block that declares a large shape therefore makes the up-front clear run far past the end of the heap destination buffer, producing a large heap-buffer-overflow write of zero bytes. The only precondition the decoder checked was that the input length was positive; the missing validation is that the declared output footprint must fit within the supplied output capacity.
