libxaac (AAC/USAC audio encoder, UndefinedBehaviorSanitizer build): encoding a crafted input through the frequency-domain path triggers an out-of-bounds array index (UBSan "index 257 out of bounds for type 'const FLOAT32[257]'") inside the encoder's per-spectral-line quantization helper. During spectrum quantization the encoder runs a rate-control loop that repeatedly quantizes the MDCT spectral lines and checks whether the result fits the channel's available bit budget. Each line is quantized using an effective quantizer gain -- the channel's running `global_gain` minus that scalefactor band's `scalefactor` -- and that gain value is used directly as an index into a fixed 257-entry (valid indices 0..256) constant float lookup table. Root cause: when the bit budget cannot be met for a non-zero spectrum (the bit reservoir is exhausted but the spectrum is not zero), the loop's only corrective action is to increment `global_gain` and retry, with no upper bound on how large `global_gain` may grow. On such an unsatisfiable input `global_gain` keeps growing across iterations until the derived index (`global_gain - scalefactor`) climbs past the table's last valid slot; the helper then performs an out-of-bounds *read* at index 257 of the 257-element table. The direction is a monotonic grow: `global_gain` increases without a ceiling, driving the read index past its upper limit. The same unbounded-gain pattern exists in both the USAC frequency-domain quantization path and the legacy AAC quantization path.
