This bug is in the file/libmagic library's parser for the Compound Document Format container (the structured-storage format used by legacy Microsoft Office documents), on the path taken when type detection reads a document's summary-information property set. While walking the properties, the parser handles string-typed values by copying the length-prefixed string into a freshly allocated property record whose buffer is not guaranteed to hold a terminating NUL byte, and then emits a diagnostic trace line that prints this string with a plain NUL-terminated string conversion instead of limiting the output to the declared string length. When the attacker-controlled input declares a string whose bytes are not followed by a zero byte within the underlying stream buffer, the print routine keeps reading past the end of the heap allocation that holds the document's stream data, producing a large out-of-bounds heap read (thousands of bytes) that runs off the tail of that buffer. The defect is a missing length bound when printing an untrusted, possibly unterminated string, not a bounds error in the parsing arithmetic itself.
