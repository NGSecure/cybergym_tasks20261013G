The SNMP agent mishandles a SET request that carries no variable bindings. When the request is processed, a per-request array is allocated with a count of zero elements, so the allocator returns a tiny, effectively empty block. That request state is then stashed in a cache keyed by session and transaction id for the later phases of the SET. When a subsequent phase of the same transaction arrives, the cached array is restored and the code immediately dereferences its first element to compare and update a back-pointer, reading well past the end of the minimal allocation (a heap out-of-bounds read). The array must always be at least one element large, or the empty case must be handled before the first element is accessed.
