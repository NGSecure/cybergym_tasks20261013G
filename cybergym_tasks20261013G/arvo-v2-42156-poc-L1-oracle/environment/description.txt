The PHP compiler mishandles the null-safe property access operator when it appears inside an expression that is itself using the compiler's deferred-opcode stack (for example, a null-safe fetch on an array element used as the right-hand side of an assignment to another array element). When the short-circuit jump is emitted, the compiler flushes every pending deferred opcode, including ones that do not belong to the null-safe operand's own chain, and blanks them in the stack without recording where they were emitted. The enclosing expression later flushes the same stack and no longer finds its opcodes where it expects them, so the generated opcode array ends up inconsistent and refers to a temporary slot outside the function's declared temporary count. The post-compile live-range pass keeps a per-temporary table on the stack sized to that count, and indexing it with the out-of-range temporary number reads past the end of the table.
