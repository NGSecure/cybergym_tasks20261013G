A heap-buffer-overflow read occurs in GraphicsMagick's MSL (Magick Scripting Language) coder, which parses scripts with an XML SAX parser and keeps a counter of currently open image groups plus a heap array of per-group records. When a group-closing element is handled, the handler unconditionally indexes that array with the open-group counter minus one and reads a 4-byte field from the selected record, without checking that any group is actually open. If the document delivers a group end tag while the counter is zero (for example an end tag that the parser reaches through nested entity-reference content, without a matching start tag having been processed by the handler), the index becomes -1 and the read lands just before the start of the heap-allocated group array, in its left redzone. The fix requires the open-group counter to be greater than zero before consulting the per-group record.
